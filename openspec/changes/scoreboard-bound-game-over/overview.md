# Overview: scoreboard-bound-game-over

## Scope

由對戰頁進入的綁定計分板打完一場後，比賽結束對話框不再提供「再來一局」（它會清掉這場還沒回填的比分），改成「返回對戰」，按下就回對戰頁、比分照常自動回填；「關閉」保留。專注模式下也一樣，因此專注模式打完不必先退出就能回對戰頁。獨立計分板完全不變。

**Size**: medium — 只影響 1 個 capability（scoreboard）、無新依賴、無架構變更，但 tasks 13 項（落在 9～20）。
**Frontend involved**: yes — 比賽結束對話框的按鈕依綁定模式改變。
**DB schema touched**: no — 後端零變更。
**Data migration**: no — 只改畫面。
**Cross-component flow**: no — 「返回對戰」只是一個連結；回到對戰頁後的回填是既有流程，順序與參與者都不變。

---

## What Changes

- `GameOverDialog`：新增可選 prop `matchId`；非 null 時 footer 為「關閉」＋「返回對戰」連結，null 時維持「關閉」＋「再來一局」。
- `Scoreboard`：把既有 `matchId` prop 傳給 `GameOverDialog`（與傳給設定列的是同一個值）。
- 主 spec：新增「比賽結束對話框的動作」；「賽前設定與階段鎖定」的 RESET 二次確認規則加上獨立模式「再來一局」這個唯一例外。

綁定場次打完後，按下對話框主要按鈕的前後對照：

```
=== Before (綁定場次，比賽結束) ===
[再來一局] -> RESET -> 分槽回 setup、分數清空
           -> 回對戰頁：沒有可回填的比分，只能手動重填

=== After ===
[返回對戰] -> 只導航到 /matchmaker（不 RESET、不寫分槽）
           -> 對戰頁讀到 finished 分槽，自動回填 11:0
```

## Architecture

資料流不變；`matchId` prop 從頁面一路傳到設定列與對話框，兩者用同一個值判斷是否綁定。

```
 app/scoreboard/page.tsx (searchParams.match)
        │ matchId prop
        ▼
 Scoreboard ──► useScoreboardStore(matchId) (不變)
   │  │
   │  ├─ bindingStatus=missing ──► MatchBindingNotice (不變，
   │  │                              對話框不渲染)
   │  ├──► ScoreboardSetup(matchId) ── [返回對戰] (不變)
   │  │
   │  └──► GameOverDialog(state, matchId, onPlayAgain=RESET)
   │          matchId != null : [關閉] [返回對戰 -> /matchmaker]
   │          matchId == null : [關閉] [再來一局 -> onPlayAgain]
   ▼
 /matchmaker：讀 finished 分槽自動回填 (不變)
```
