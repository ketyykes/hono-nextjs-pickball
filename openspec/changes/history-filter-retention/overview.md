# Overview: history-filter-retention

## Scope

登入時的雲端歷史頁與統計頁，切換區間或載入失敗時不再把區間篩選器整個拿掉：篩選器（統計頁連同標題）保留在原處、鍵盤焦點留在剛選的區間，只有紀錄清單或排行榜那一塊換成「載入中」或「載入失敗」提示。
載入失敗後可以直接改選其他區間重新載入。訪客（本機）頁面完全不變。

**Size**: medium — 影響 2 個 capability（match-history、player-stats），tasks 18 項（9～20），無新依賴、無架構變更。
**Frontend involved**: yes — 兩個雲端元件在載入中／失敗時的畫面結構與焦點行為改變。
**DB schema touched**: no — 後端零變更。
**Data migration**: no — 只改畫面。
**Cross-component flow**: no — 仍是「選區間 → GET 歷史 → 顯示」的單一請求，流程與順序不變；改的只是請求進行中與失敗時畫面的哪一塊被替換。

---

## What Changes

- `RemoteHistoryView`：載入中／失敗時保留篩選器，只替換紀錄區塊；篩選器全程是同一個 DOM 元素。
- `RemoteStatsContent`：歷史載入中／失敗時保留標題與篩選器，只替換排行榜；名單載入中／失敗時維持整段取代。
- 主 spec：改寫「載入失敗時歷史頁顯示錯誤」的「區間篩選不存在」，新增焦點與重新載入的 Scenario。

切換區間時畫面結構的前後對照：

```
=== Before (登入時，切換區間) ===
synced  : [篩選器] [紀錄清單]
loading : [載入中提示]                 <- 篩選器卸載，焦點掉回 body
failed  : [失敗提示]                   <- 無法改選區間，只能重新整理

=== After ===
synced  : [篩選器] [紀錄清單]
loading : [篩選器] [載入中提示]        <- 同一個篩選器，焦點不動
failed  : [篩選器] [失敗提示]          <- 改選其他區間即重新載入
```

## Architecture

元件與資料流不變，只有兩個雲端元件內部的渲染結構調整；訪客路徑與 hook 不動。

```
 HistoryModeSwitch ──remote──► RemoteHistoryView ─┐
        └──local──► HistoryView (不變)            │
                                                  ├─► useRemoteHistory (不變)
 stats/page.tsx ──remote──► RemoteStatsContent ───┘         │
        └──local──► LocalStatsContent (不變)                ▼
                                               GET /api/matchmaker/history

 RemoteHistoryView / RemoteStatsContent 內部（After）：
 ┌ root[data-sync-status] ───────────────────────────────┐
 │ [標題 (統計頁)] [損毀提示?] [HistoryRangeFilter 固定位置] │
 │ [內容槽: SyncStatusNotice | 紀錄/排行榜 | 空狀態]        │
 └────────────────────────────────────────────────────────┘
 統計頁名單阻斷時：root 只含 SyncStatusNotice（不變）
```
