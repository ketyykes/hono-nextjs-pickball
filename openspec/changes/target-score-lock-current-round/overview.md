# Overview: target-score-lock-current-round

## Scope

訪客在前一輪留下「計分中」的場次（計分板打到一半就改用手動送分，或直接產生下一輪）時，新一輪的目標分數與計時設定一產生就被鎖死。
本 change 讓鎖定判定只看本輪場次的計分板進度，前一輪留下的進度不再影響新一輪。

**Size**: small — 只影響 1 個 capability（round-lifecycle），產品碼只改一個函式，tasks 14 項，無新依賴、無架構變更。
**Frontend involved**: yes — 對戰頁「本輪設定」的目標分數與計時控制項在殘留情境下由停用改為可操作。
**DB schema touched**: no — 後端零變更。
**Data migration**: no — 不清除也不轉換任何既有 LocalStorage 資料。
**Cross-component flow**: no — 仍是「對戰頁讀槽 → 純函式判定 → 控制項停用與否」的同步計算。

---

## What Changes

- `isTargetScoreLocked` 的第二條只計入鍵為本輪場次 id 的計分板槽。
- 目標分數與計時（共用同一個判定）一併修正；雲端模式同樣經過此函式。
- 刪除一個釘住舊行為（孤兒槽也鎖定）的既有 it，由新 it 承接相反期望。
- 不清除殘留槽（另案處理）。

判定輸入與結果的前後對照：

```
round.matches = [new1]          slots = { old1: playing }

=== Before ===
anyMatchStarted = false
anySlotStarted  = old1 playing          -> true
locked          = true   (new round is stuck)

=== After ===
anyMatchStarted = false
anySlotStarted  = only keys in {new1}   -> false
locked          = false
```
