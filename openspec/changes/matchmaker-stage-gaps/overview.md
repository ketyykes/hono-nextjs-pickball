# Overview: matchmaker-stage-gaps

## Scope

補三個已合併程式碼裡早就存在、但畫面上完全沉默的小缺口：本輪場次被重排到剩 0 場時畫面沒有任何說明文字、歷史頁從不顯示「有幾筆紀錄因損毀被略過」、以及「重設／再排」這顆按鈕從未被任何 E2E 真正點擊過。三項底層邏輯皆已正確且有既有測試覆蓋，本 change 只補**畫面消費**與**測試覆蓋**，不動任何 `lib/matchmaker/**` 檔案。

**Size**: medium — 影響 2 個 capability（`match-stage`、`match-history`），落在「2-3 capabilities」區間；tasks.md 共 20 項，落在「9-20」區間，兩個判準一致收斂於 medium。
**Frontend involved**: yes — 三項工作皆為元件層的畫面呈現改動（新增一個空狀態元件、修改兩個既有元件）。
**DB schema touched**: no — matchmaker 為 LocalStorage-only 純前端功能，本 change 不新增、不修改任何 schema 或 storage key。
**Data migration**: no — 不搬移、不轉換任何既有資料，三項工作皆為唯讀消費既有資料結構。
**Cross-component flow**: no — 三項互動皆是「使用者操作 → 純函式回傳新狀態 → 元件重新渲染」的單次同步流程（等同前端內部的一來一回，沒有非同步任務、webhook、排程或多服務協作），不需要時序圖。

---

## What Changes

- 對戰頁：`round.matches` 為空但 `round` 存在時，新增元件 `EmptyMatches.tsx` 顯示說明與「前往參賽者名單」入口，取代原本無內容的空網格。
- 歷史頁：`HistoryView.tsx` 開始消費 `readHistory()` 既有回傳的 `droppedCount`，`> 0` 時顯示與 `player-roster` 既有損毀提示同樣式的繁體中文提示。
- 測試：`tests/e2e/specs/match-stage.spec.ts` 新增「重設／再排」的完整端到端覆蓋（不修改任何 Requirement）。

Before / after 對照（純文字、無 UI 細節）：

```
=== Before ===

  對戰頁 /matchmaker      : round.matches 為空時 -- 畫面只剩休息名單, 場地區塊
                            一片空白, 無任何文字
  歷史頁 /matchmaker/history : 讀到損毀紀錄時 -- droppedCount 存在於 readHistory()
                            回傳值, 但沒有任何畫面消費它, 使用者不知道少了幾筆
  重設／再排 E2E 覆蓋      : match-stage.spec.ts 只在無關測試裡順手驗過按鈕
                            的可存取名稱, 從未真正點擊過

=== After ===

  對戰頁 /matchmaker      : round.matches 為空時 -- 顯示「本輪目前沒有任何
                            場次」與前往參賽者名單的入口
  歷史頁 /matchmaker/history : droppedCount > 0 時 -- role=alert 提示
                            「有 N 筆損毀的歷史紀錄已略過, 其餘歷史紀錄不受影響」
  重設／再排 E2E 覆蓋      : 完整走一次產生 -> 送出比分 -> 重設／再排, 驗證
                            已完成場次保留、未完成場次重新分配、休息名單更新
```

## Architecture

三項工作彼此獨立、不共用任何新檔案，重點是**皆為既有純函式的新消費端**，不新增任何 `lib/matchmaker/**` 邏輯。

```
┌──────────────────────┐        ┌──────────────────────────┐
│  MatchStage.tsx       │  round.matches.length === 0        │
│  (M5 既有, 本 change   │ ─────────────────────────────────► │
│   只加一個條件分支)    │                                    │
└──────────┬────────────┘                                    │
           │ length > 0                                       ▼
           ▼                                        ┌──────────────────┐
┌──────────────────────┐                            │ EmptyMatches.tsx  │
│  CourtCard 網格        │                            │ (新增, 零 props,  │
│  (既有, 不變)          │                            │  純呈現, e2e 驗收)│
└──────────────────────┘                            └──────────────────┘

┌──────────────────────┐     readHistory()      ┌──────────────────────┐
│  HistoryView.tsx       │ ◄─────────────────────  │ round-storage.ts      │
│  (既有, 本 change 多    │   { entries,           │ (M4/M7 既有, 本 change │
│   取用 droppedCount)   │     droppedCount }      │  零修改)               │
└──────────┬────────────┘                         └──────────────────────┘
           │ droppedCount > 0
           ▼
   role="alert" 提示（樣式比照 player-roster 既有的
   app/matchmaker/players/page.tsx，各自持有一份，不共用元件）

  外部相依 (皆唯讀取用, 本 change 不修改):
    round-lifecycle : resetIncompleteMatches, readHistory, MatchHistoryEntry
    player-roster   : app/matchmaker/players/page.tsx 的既有提示樣式（僅參考）
  npm 相依: 零新增
```
